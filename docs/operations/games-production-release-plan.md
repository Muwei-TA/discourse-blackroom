# BlackRoom 游戏板块正式上线计划与执行结果

> 原计划编制于 2026-10-12；用户随后授权执行，10 月 12 日晚已正式上线。以下保留接入契约与原任务要求，执行结果和未完成的证据项分别记录。后续变更按当前授权边界判断，不因历史计划重设批准节点。

**Goal:** 将仅正常登录成员可玩的桌面网页游戏正式接入 BlackRoom，并保持平台入口、身份桥、网关和游戏程序各自独立。

**Architecture:** 论坛提供目录、说明、讨论和通用授权接口；浏览器在独立新页面通过游戏网关访问 Docker 游戏。网关使用同一通用镜像，但每款游戏运行自己的网关实例，游戏升级或某一网关故障不要求重启其他游戏或论坛。平台发布与游戏版本更新解耦，只依赖稳定的对外接入契约。

**Tech Stack:** Discourse 原生分区/话题、独立主题组件、小型 Ruby 授权插件、Node 标准库 HTTP/WebSocket 网关、Docker Compose、现有 Pangolin/Newt 公网入口；Cloudflare 操作使用 `cf` CLI。

**Spec:** [游戏接入需求与权限契约](games-integration-plan.md)，及本计划的模块化约束。

更新日期：2026-10-13，北京时间。状态：正式站点已开放游戏入口，持续观察进行中；两名真实学生、音频硬件及新完整数据库恢复演练不在已完成证据内。

## 全局约束

- 仅正常登录成员可玩，保留原生会话、CSRF、用户状态及 Guardian 检查；社团私有分区权限不变。
- 新页面游玩、原论坛保留；默认只支持桌面，不开发或验收手机 UI、触摸控制。
- 游戏源码、玩法、房间、游戏数据和依赖留在各自游戏项目；不引入 Discourse 核心、不共享论坛数据库、不与论坛构建绑定。
- 不做自动发现、调度平台、积分、排行榜或跨游戏账号系统。游戏清单由管理员维护，成员只能使用已登记入口。
- 启动票据 60 秒、单次原子消费，不出现在 URL；生产游戏 Cookie 使用 Secure、HttpOnly、host-only、SameSite=Strict。
- 退出登录、封禁或验证服务不可用后，已建立连接必须在 60 秒内关闭；不可承诺论坛认证停机期间仍继续游玩。
- 原有 3001/3002 游戏、社团数据、上传、邮件插件、未提交修改和回退材料全部保护；生产备份只存指定 NAS `/vol4` 路径。

## 发布前五项重点验证

1. 浏览器使用的论坛域名与服务器配置域名不同，启动 Origin、Cookie 或邀请重入仍须正确；不放宽 Origin 为通配符。
2. 游戏或游戏配置失败，只影响游戏入口/对应游戏；普通话题不发起游戏目录或授权请求，伪造游戏Cookie不得触发论坛查询。
3. 游戏更新后仍遵守对外接入契约，平台入口与授权应继续可用；只有接入契约发生变化时调整配置并验收受影响路径。游戏玩法或内部协议更新不作为平台发版前置条件。
4. 镜像、YAML 声明与实际挂载不一致，插件及邮件适配器必须在启动前后均可恢复和持久加载。
5. 原端口、IPv6、备用域名或隧道资源仍能直连未认证游戏，必须阻止绕过；隐藏入口不算门禁。

唯一清单字段固定为：`forum_origin`、`forum_internal`、`category_slug`、`games[]`；每项含 `id`、`title`、`description`、`origin`、`upstream`、`websocket_paths`，规则项为 `{path, match}`，match 仅 exact/prefix。`topic_id` 与 `category_id` 在论坛原生对象创建后回读至部署状态，不硬编码、不伪称已创建。`forumState` 固定为 `{category_id, topic_ids: {game_id: topic_id}}`；内部验证地址从发行清单的 forum_internal 生成。平台镜像摘要与清单摘要进入发行记录；游戏镜像摘要独立记入运维快照。

`config.mjs` 提供 `validateManifest(manifest)` 与 `renderConfigs(manifest, forumState, gatewayKey)`：校验失败不生成或应用文件；返回论坛配置与按游戏拆分的网关配置。论坛配置只包含公开目录、回读的对象 ID 与私有服务认证 key，不包含游戏上游地址；网关配置包含该游戏固定上游与认证信息。CLI 不打印密钥，私有文件权限 0600，不进入 Git。

网络采用每款游戏独立内部 backend 网络，以及一个连接器可达的 gateway ingress 网络。网关加入自身 backend 与 ingress；游戏只加入自身 backend；Newt 仅通过 ingress 访问网关，不加入游戏 backend。网关仍可经已确认的内部路径访问论坛授权 API；不改变论坛已有 bridge 网络，不向游戏开放 Docker socket、论坛卷或数据库。

网关签名Cookie仍只携带不透明授权引用及到期信息，不把用户资料或论坛凭据交给游戏。每实例限制论坛校验的并发与排队，同一授权的请求合并；认证异常仍在60秒上限内关闭HTTP与WS，避免游戏请求耗尽论坛工作进程。

已应用的资源限制：每款游戏 1 CPU/512 MiB，每个网关 0.5 CPU/256 MiB；非 root 网关、源码/配置只读、必要 tmpfs、no-new-privileges、cap_drop ALL、日志轮转、健康检查及 restart unless-stopped。已完成隔离 8/12 协议客户端的限定工况，不能据此推定长期或全站容量。

## 稳定接入契约与独立更新

平台仅消费游戏的网页入口、静态资源、HTTP/实时连接传输与邀请地址。每款游戏承诺：固定公开来源和根路径、登记的上游地址与 WebSocket/Socket.IO 路径、可经代理工作的 Host/Origin，以及可透传的房间邀请参数。房间标识视为不透明值，只做长度、字符和编码边界校验，不解释游戏房间内容。

游戏客户端与服务端自身负责建房、加入、玩法及内部消息协议。内部消息格式可以随同一游戏更新，通用网关不解析它，也不将它作为平台接口版本。稳定接入契约未变时，游戏项目自行构建、部署、冒烟检查与回退；不修改论坛代码、不发布主题/插件/网关、不要求平台重复整套验收。只在来源、路由、传输方式或邀请参数约定发生变化时调整登记配置/必要适配并定向复测。

游戏升级若重启容器，当前内存房间可能结束；这是该游戏服务的维护影响，论坛入口及其他游戏继续使用。平台故障隔离不等于升级过程中该游戏连接可以无缝迁移。

## 多房间行为与责任

平台完成登录验证并打开游戏页面，不创建房间、不替用户选房。当前两款游戏均在同一游戏容器里维护多个独立房间：点击创建生成新房间标识，输入房间码或使用邀请链接才请求加入指定房间。第二个人打开游戏首页不会因已有房间自动加入；点击创建会建立另一间房。达到容量上限时创建/加入可能拒绝，不自动分配另一容器或房间。

房间成员、状态和消息由游戏自身按房间隔离，平台成员门禁不替代游戏的房间规则。首版不增加自动匹配、平台房间列表或每房间一容器。首次接入验收覆盖独立建房、指定加入和两房间互不串扰；后续游戏维护由游戏项目验证房间逻辑。

## 域名与成员登录策略

按用户指定，默认游戏启动平台入口为 `https://discourse.muwei.xyz`。游戏已使用 `https://bonk.muwei.xyz`、`https://skribbl.muwei.xyz`，对应两个独立游戏服务；正式证书与 Pangolin/Newt 路由已经落地。

保持现有 Rails base_url 与其他站点页面不变。首版只允许 `https://discourse.muwei.xyz` 作为游戏启动 Origin；已有 `blackroom.qzz.io` 别名上的游戏入口链接到该来源的同一说明话题，保留房间参数，必要时完成该来源的原生登录。不跨域复制论坛 Cookie，也不声称两个论坛域名的登录自动互通。主题生成服务端登记的启动平台链接，不能让客户端指定回调。

上线前必须确认所选域名可控制、证书覆盖、真实浏览器认定同站点，且 Secure/Strict 游戏 Cookie在 POST 兑换后的新页、刷新与 WS 请求中可用。若预检失败，保留问题与具体域名差异；不在执行中更换论坛入口、改 Cookie 策略或扩大 Origin 白名单。

论坛内部验证地址与外部启动 Origin 分开记录。必须在候选环境验证 force_https、Host 与代理转发不会造成重定向循环；不使用关闭 TLS 校验或关闭全站 HTTPS 的方式绕过。

## 任务 2：完成通用化与入口隔离

**输入：** 已验收基础提交与固定清单接口。**产出：** 不含游戏专用分支的接入代码、可生成的配置、定向测试。

## 回退顺序与触发条件

认证绕过、源站仍可匿名直连、已有连接超过60秒未收回、论坛登录/普通话题故障、OOM/反复重启，立即停止开放。

1. 先关闭受影响游戏的公网路由与网关，并在生成的授权配置中移除该游戏登记，收回已有授权；保留源站内网和数据。共有身份桥故障时关闭全部游戏入口。
2. 界面问题只解除游戏主题组件/侧栏关联；保留分区、帖子、回复。插件问题定向撤销本次加载与代码并按实际方式重启，不能通过恢复整个论坛数据库回退UI。
3. 游戏问题使用保存的上一镜像及独立 Compose恢复该游戏；网关问题回退对应实例。旧内存房间无法恢复，成员需重新建房。
4. 源站端口不能默认恢复为LAN/公网匿名访问。确需恢复旧访问范围，须按最终批准清单的授权边界执行；未覆盖则保留维护状态再申请具体动作授权。
5. 本功能没有数据库迁移，正常回退不覆盖生产库；生产数据恢复另走 resilience.md 的具体恢复批准流程。失败日志、旧版本与备份不清理。
