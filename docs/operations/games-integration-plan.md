# BlackRoom 网页游戏接入计划

日期：2026-10-12。范围：已获授权在隔离测试环境执行和验收；生产发布另行确定。

正式发布采用[模块化上线计划](games-production-release-plan.md)。本文件的“已同步/已验收”以当时测试版本为准。平台与游戏更新独立：只依赖稳定的对外接入契约，游戏内部更新不要求平台同步镜像或重复整套验收。

## 当前需求

- 仅 BlackRoom 正常登录成员可玩，包括不同社团成员和未加入社团的正常成员。
- 在论坛「游戏」分区查看卡片、说明和原生话题讨论；点击「在新页面开始游戏」，在独立游戏页面游玩，论坛页面保留。
- 默认只支持桌面端，不开发或验收手机 UI、触摸控制。
- NAS 3001、3002 提供独立游戏服务；此前按用户要求同步过隔离测试副本。后续游戏版本由各自项目维护，对外接入契约稳定时不与平台发版绑定。
- 不增加积分、排行榜、跨游戏账户或自动发现服务，不修改既有社团权限。

## 实现

登录成员 → 游戏说明话题 → 原生 POST 表单在新标签页打开 → 论坛验证当前会话 → 单次票据通过 POST 送到游戏网关 → 网关设置专用 Cookie 并重定向到游戏首页或邀请房间。

采用独立主题组件、小型 Discourse 插件和 Node 标准库 HTTP/WebSocket 网关。两款游戏分别保持独立来源和根路径，保留 `/ws`、`/socket.io`、静态资源和 `?id=` 房间邀请。论坛组件只展示入口，不再创建 iframe、监听跨窗口消息或承担游戏全屏/退出状态；退出通过关闭游戏页面，全屏使用桌面浏览器自身功能。

新页由用户点击的原生表单打开，保留 CSRF 校验，并用 `rel="noopener"` 切断游戏页面对论坛窗口的访问。论坛返回仅负责自动提交票据的过渡文档，配置精确 nonce CSP 与唯一 `form-action`；票据不放在 URL。关闭脚本时保留手动提交按钮。

测试域名为 `forum.games.localhost:18190`、`bonk.games.localhost:18192`、`skribbl.games.localhost:18193`，仅通过这台 Mac 的回环桥接可达。按用户指定，正式平台入口默认为 `https://discourse.muwei.xyz`；游戏拟使用 `https://bonk.muwei.xyz`、`https://skribbl.muwei.xyz`，保留各自根路径。已有 `blackroom.qzz.io` 别名的游戏入口跳回默认平台来源并保留邀请参数，必要时走该来源原生登录；不改变其他页面或复制跨域 Cookie。当前未配置公网游戏域名、DNS 或 TLS。

## 游戏接入与房间契约

平台负责目录、成员授权与新页面入口；游戏负责建房、加入、对局与数据。通用网关只代理 HTTP、WebSocket/Socket.IO，不解析游戏内部消息。稳定契约限于公开来源、根路径/资源、上游地址、实时连接路径、Host/Origin及可透传的邀请参数；内部玩法和消息协议更新由游戏自身维护。

打开游戏首页不自动建房。玩家A已创建房间A，玩家B点击创建会得到独立房间B；B用A的房间码或邀请链接加入，才进入A。两款游戏均支持同一游戏容器管理多间房，不为每名玩家或每间房启动Docker；不存在、已开始或满房等失败按游戏规则提示，不自动加入另一房间。平台不增加匹配或房间列表。

## 权限契约

- 只接受固定 `bonk`、`skribbl` 和服务器登记的目标，不能指定任意上游、回调或用户身份。
- 启动要求原生浏览器 `UserAuthToken` 属于当前用户，不接受管理员模拟身份或 API 身份代替登录。
- 票据随机、高熵、60 秒有效、Redis 原子消费一次，绑定游戏、用户、当前会话和启动状态。
- 网关 Cookie 为 host-only、HttpOnly；生产要求 HTTPS/Secure。当前 localhost 隔离测试明确采用 HTTP，不据此声称 TLS/WSS 已验收。
- 网关只接受论坛精确 Origin 的启动 POST；业务 HTTP、polling、WebSocket 均检验专用授权。
- 论坛 Cookie、服务认证 key、Discourse API 身份头不传到游戏源站。
- 当前会话注销、过期、账号停用/封禁或板块权限失效时拒绝后续请求，并周期性关闭已建立实时连接。网关每 15 秒并行验证活跃授权，论坛验证超时 4 秒；验收上限 60 秒。
- 复制邀请地址不等于授权。已授权成员直接进入房间；无授权的顶层游戏入口回到论坛说明话题并保留房间参数。
- 不再允许游戏被嵌入，游戏响应使用 `frame-ancestors 'none'`；不修改论坛全站 CSP 或正文 iframe 白名单。

## 测试环境与同步

NAS 使用 `blackroom-games-test-20261012` 前缀，内部 Docker 网络 `172.16.245.0/28`，无发布端口、无外网连接。论坛使用新建数据卷、新迁移数据库及合成测试成员；不恢复生产数据。禁用测试邮件、Sidekiq、cron/anacron，清除生产镜像继承的环境配置。

游戏更新同步仅替换两个测试容器，保留旧测试容器作为回退。原 3001/3002 容器保持运行。当时同步前后记录容器 ID、精确镜像、重启次数，并核对当时端口镜像与测试镜像相同。这是历史测试记录，不是后续发布约束。游戏更新仍符合对外接入契约时无需重新同步平台测试镜像；接入契约变化才调整配置并定向复测。

## 实施与验收

1. 将新页面方案落实到主题入口、论坛启动接口、网关交换及邀请跳转；删除内嵌实现与过时检查。
2. 在隔离环境验证符合对外接入契约的游戏服务并加载插件与主题，保留原测试数据和生产现场；独立记录游戏版本，不要求与平台锁定同一发布节奏。
3. 验证匿名、未激活/封禁、失效会话、过期/重放票据、跨游戏替换、伪造身份头和错误 Origin 均不能绕过门禁。验证社团 A、社团 B、普通成员及管理员的正向访问，私有社团继续隔离。
4. 桌面浏览器验证新页面打开、原论坛保留、入口切换、邀请参数、刷新重入、游戏按钮/键盘/绘图及控制台。真实页面证据与协议自动化、服务端合成身份验证分开记录。
5. 两名授权测试玩家完成黑房弹球同房间对局与比分、你画我猜创建/邀请、绘图同步、猜词与计分；追加同款游戏分别建两房间、两房间互不串扰以及通过指定邀请加入的验证；检查注销和封禁后已有实时连接在 60 秒内断开。不能把首页或握手成功当作对局验收。
6. 运行相关网关测试、服务端断言、主题编译和一次定向 `bin/lint --fix`。不跑无关全库检查，也不向生产批量安装开发依赖。
7. 保存验收记录、截图、精确镜像与可复现入口。测试验收不触发生产公告或教程发布。

## 生产发布与回退边界

本次不修改生产插件、主题、源站端口、容器网络、DNS、证书或公网路由。未来上线需先核验当前房间与使用者，准备 NAS `/vol4/1000/backup/blackroom/game-releases/` 下可验证的源码、配置及回退材料，再确定具体切换范围与授权。

生产游戏必须只对网关开放；否则用户仍可通过旧 3001/3002 绕过论坛身份。这属于将来的端口收紧动作，当前测试不会改变已有访问范围。界面回退解除主题组件，不删分区或帖子；安全故障先关闭网关入口，保留内部游戏、源码和数据。

公共 HTTPS/WSS、真实学生账户、公网访问/原端口绕过及并发容量属于生产阶段验收；手机端按用户要求不纳入范围。
