# 游戏默认站点用户名接入方案

> 编制日期：2026-10-13。用户已授权按方案同时修改平台与两款游戏，本功能已部署并完成正式 Chrome 验收。执行结果见 [游戏平台运维](games.md)，截图见 `outputs/games-release/games-username-20261013/`。下文保留设计与实施检查项，不新增例行批准节点。

**Goal:** 已登录成员打开游戏后，昵称默认填入其当前站点 `username`，仍可手动修改游戏昵称。

**Architecture:** 论坛授权插件从有效 grant 找到当前原生用户；游戏网关提供受现有成员门禁保护的同源玩家资料接口。两款游戏只消费统一接口，与 Discourse 的 Cookie、API key、内部模型和建房逻辑解耦。

**Tech Stack:** 现有 Discourse Ruby 插件、Node 标准库网关、弹球 TypeScript 前端、绘画原生 JavaScript 前端及昵称字段验证；不新增依赖或数据库迁移。

**Spec:** 用户本轮默认昵称要求及 [现有游戏平台接入契约](games.md)。

## 现场证据与范围

| 对象 | 当前行为 | 修改范围 |
| --- | --- | --- |
| 论坛插件 | ticket/grant 保存 user_id/token_id；verify 仅返回 204，没有玩家资料接口 | 从有效会话读取 username，增加内部 profile 动作 |
| 游戏网关 | 游戏资源透传，`/_blackroom/` 未登记路径返回 404 | 增加统一 `GET /_blackroom/me`，其他游戏资源继续透传 |
| 弹球 | NAS `src/client/ui.ts` 只读取手填 nickname，运行 bundle 无 username/nickname 查询参数支持 | UI 初始化获取接口并填入昵称 |
| 你画我猜 | NAS及运行实例 `public/js/avatar.js` 从游戏域名 localStorage.name 恢复旧昵称 | 获取接口并同步 playerName.value 与 my.name，当前站点名优先于旧缓存 |
| 你画我猜昵称长度 | 当前前后端上限 32 个 UTF-16 码元；站点 max_username_length=20，unicode_usernames=true | 昵称字段按 Unicode 字符计数保留 32 字符上限，同步输入框；覆盖非 BMP 字符，不改其他字段验证 |

游戏域名与站点不同，论坛页面不能写入游戏域名的 localStorage。两款游戏目前没有现成昵称参数契约。通过网关改写游戏 HTML、注入针对具体输入框的脚本虽能做出效果，但会把游戏 DOM 和版本细节放进平台，破坏现有独立更新契约，因此不采用。

## 接口与行为契约

- 论坛内部：`POST /blackroom-games/profile`，沿用网关服务 key 认证，输入 grant/game；复用现有有效原生会话、账号及板块权限检查，返回 `{ "username": "站点用户名" }`。按 grant 对应 user_id 实时读取，不接受客户端传入用户名。
- 游戏同源：`GET /_blackroom/me`，网关校验登记 Host、游戏绑定及有效签名授权，再取上述资料。成功 200，仅返回 username；未登录/失效 401，服务暂不可用返回适当 5xx。设置 `Cache-Control: no-store`，不开放跨域读取；现有 verify 的 204 契约保持兼容。
- 玩家资料接口不把论坛 Cookie、服务 key、grant 原文或个人邮箱交给游戏 JavaScript，用户名也不进入游戏 URL 或邀请链接。
- 使用 `username` 而非站点展示名；仅默认填写，不锁定、不自动建房、不把修改后的游戏昵称回写论坛。
- 每次新打开游戏按当前登录用户默认填写，刷新也重新取当前站点名；论坛改名后下次进入同步。旧游戏昵称缓存不能覆盖当前站点名，同一浏览器换账号不得沿用前一人的默认昵称。
- 已在资料返回前手动输入昵称时，不覆盖该输入。资料暂时不可用或游戏单独运行时，留空供手填；不自动恢复未知归属的旧昵称缓存。成员门禁本身仍按现有流程执行，不因昵称接口失败开放访问。

## Review Focus

- 原生中文及非 BMP 用户名长度、编码和显示完整；不要截断造成重名。
- 已有 localStorage.name 与换账号场景；旧缓存不得盖过当前用户默认值。
- 资料请求较慢时的手动输入、建房与加入；不覆盖已输入内容或已开始的对局。
- 无授权、过期、跨游戏、伪造 Cookie 与参数；资料接口必须保持现有门禁。
- 邀请、刷新、直接启动和游戏独立运行；昵称接入不改变房间选择或其他游戏流程。

## 回退与独立更新

游戏可分别回退到原镜像，旧游戏不会调用新资料接口，继续手填昵称；新游戏在接口暂缺时也保留手填回退。平台资料接口的字段与路径稳定后，兼容的游戏版本更新无需改动论坛代码。不要为了默认昵称改变房间协议、创建游戏账号、引入用户数据同步表或复制论坛登录凭据。
